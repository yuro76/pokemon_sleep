# 次の週のフィールドランキング

次の週(月曜 4:00〜翌月曜 4:00)にどのフィールドへ行くのが良いか、ランキング形式で出す。

ユーザーの指定: $ARGUMENTS
(空なら次の月曜からの1週間。日付があれば `--week`、「〇〇は未開放」なら `--exclude`、
「ぐっすり寄り」など睡眠タイプの指定があれば `--sleep-type` に変換する)

ツール: `python3 .claude/skills/pokesleep-iv/scripts/field_rank.py` (リポジトリのルートで実行)

## 優先順位

1. **イベントがある場合**: 特定のフィールドにメリットがある(対象フィールド・好きなきのみの固定・
   対象タイプが好きなきのみに入っている)フィールドや、**新規登場ポケモン**が出るフィールドを優先
2. **イベントがない場合**: 最新の厳選状況 (`records/pokemon.json`) と各フィールドの出現ポケモンを照らし合わせ、
   **食材タイプで厳選完了できていないポケモン**が多く出るフィールドを優先
   (記録なし=1点、キープのみ=0.5点、そのフィールドでしか出ない=+0.5点)

## 手順

### 1. データを最新にする

```bash
python3 .claude/skills/pokesleep-iv/scripts/update_data.py
```

イベント (`data/events.json`) と新ポケモンの実装日 (`data/pokemon.json` の `arrival`) が更新される。
失敗しても既存データで続行してよい(その旨を最後に添える)。

### 2. イベントを確認する

`data/events.json` は有志のツールのデータなので、告知直後のイベントが入っていないことがある。
**対象週のイベント・新ポケモン・フィールド限定の情報を WebSearch で調べる**
(例: 「ポケモンスリープ イベント 〇月〇日」「ポケモンスリープ 新ポケモン 追加」「Pokémon Sleep event」)。
公式サイト (pokemonsleep.net) のお知らせ・公式 X の情報を優先する。

`field_rank.py` の出力の「イベント」欄にないものが見つかったら、スクラッチパッドに JSON を書いて `--events` で渡す:

```json
[{"name": "ハロウィン2026", "start": "2026-10-19T04:00", "end": "2026-10-26T04:00",
  "fields": ["ワカクサ本島"], "pokemon": ["ゴース", "ピカチュウ (ハロウィン)"], "types": ["ゴースト"],
  "memo": "ゴーストタイプの食材+1、ワカクサ本島の好きなきのみにブリーのみが固定"}]
```

- `fields`: メリットがあるフィールド。全フィールド共通のイベント(料理大成功UP など)なら空にする
- `pokemon`: 新登場・期間限定で出るポケモン。出現フィールドが分かれば `fields` にも入れる
- `types`: 出やすくなる・ボーナスがあるタイプ(日本語名でも英語でも可)
- 時刻は日本時間。イベント期間が対象週と重なっていなければ無視される

調べても何も見つからなければ、`--events` なしで実行してよい。

### 3. ランキングを出す

記録はセッション(ブランチ)ごとに更新されていくので、`field_rank.py` は `git fetch` したうえで
**全ブランチの `records/pokemon.json` のうち最後に更新されたもの**(手元に未コミットの変更があればそれ)を使う。
出力の「記録の出どころ」「記録済み」で、どの記録を使ったか・想定の個体が入っているかを確認する。
ユーザーが登録したはずの個体が入っていなければ、その旨を伝える(別の場所に記録があるかもしれないので)。

```bash
python3 .claude/skills/pokesleep-iv/scripts/field_rank.py [--week YYYY-MM-DD] [--events <JSON>] \
  [--exclude <フィールド> ...] [--sleep-type うとうと|すやすや|ぐっすり ...] [--top 3]
```

### 4. 結果をユーザーに伝える

出力をもとに、日本語で次をまとめる。

1. 対象期間と、見つかったイベント(なければ「イベントなし」)。WebSearch で調べた内容には出典リンクを付ける
   。使った記録(出どころのブランチ・件数)も一言添える
2. **ランキング表**(順位・フィールド・理由)。1位の理由は具体的に
   (例:「イベント対象で好きなきのみにマゴのみ固定」「食材タイプの未厳選が13種、うち7種はここでしか出ない」)
3. 上位フィールドで狙うポケモン(食材タイプで厳選が終わっていないもの。★ここでしか出ない ものを先に)
4. 注意点
   - 出現ポケモンのデータがないフィールド(ワカクサ本島)は厳選スコアを出せていないこと
   - 出現データの時点より後に追加されたポケモンは反映されていない可能性
   - フィールドランクが低いと出ないポケモンもいること、睡眠タイプの偏りで出会える子が変わること
   - 厳選状況は `pokesleep-iv` スキルで記録した個体だけを見ていること

### 5. データの更新をコミットする

手順1で `data/` 配下が更新されていたら、コミットして作業中のブランチにプッシュする
(クラウド環境ではコミットしないと消えるため)。

```bash
git add .claude/skills/pokesleep-iv/data
git commit -m "データ更新: イベント・ポケモン"
git push -u origin <現在のブランチ>
```

## データについて

- 出現ポケモン: `.claude/skills/pokesleep-iv/data/fields.json`。
  `python3 .claude/skills/pokesleep-iv/scripts/update_fields.py` で Serebii
  (つながらなければ sleepbox-compass の Serebii 由来データ)から再生成する。
  ワカクサ本島はデータがないので、分かれば `encounters` に睡眠タイプ別の英語名 (`pokemon.json` の `name_en`) で追記してよい
- EX フィールドは元のフィールドと同じ出現とみなし、イベントの対象になった時だけランキングに出る
