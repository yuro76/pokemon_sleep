# ポケモンスリープ 個体評価・記録

スクショから個体を読み取り → 計算・比較 → ユーザーに結果を見せる → **ユーザーが了承したら**記録する。

ツール: `python3 .claude/skills/pokesleep-iv/scripts/pokesleep.py <サブコマンド>`
(以下 `PS` と書く。リポジトリのルートで実行する)

| サブコマンド | 用途 |
|---|---|
| `PS lookup <名前>` | 基礎データと各食材枠の選択肢(個数つき)を表示 |
| `PS eval <JSON>` | 評価 + 記録済み個体との比較 (`-` で標準入力) |
| `PS save <JSON> --status 厳選完了\|キープ` | 記録に追加 |
| `PS list [--name 名前]` | 記録一覧 |
| `PS update <ID> <JSON> [--status ...]` | 記録を部分更新 (レベルアップ・進化・スキルLvなど) |
| `PS delete <ID>` | 記録を削除 |
| `PS require [名前 サブスキル...] [--clear]` | 必須サブスキルの設定・解除・一覧(引数なし) |

記録は `records/pokemon.json`、必須サブスキルの設定は `records/required_subskills.json` に保存される。

## 手順

### 1. スクショを読み取る

ポケモン詳細画面から次を読み取る。1枚に収まっていなければ、足りない部分のスクショを追加で頼む。

- **ポケモン名**(フォルム違いは `ピカチュウ (ハロウィン)` のように。ニックネームが付いていれば種族名を特定し、ニックネームは `nickname` に)
- **レベル**
- **せいかく**
- **サブスキル** 5つを **Lv10 → 25 → 50 → 70 → 80 の順で**(未解放のグレー表示も含める)
- **食材** Lv1 / Lv30 / Lv60 枠のアイコンと個数(未解放の枠も含める)
- **メインスキルのレベル**
- **RP**(画面に出ていれば。読み取りミスの検出に使う)
- せいかく欄に**葉マーク**があり「せいかくによる特徴なし」と出ていたら、ミントで補正を消している。せいかく名はそのままで `"mint": true`
- 分かれば **おやすみリボン**の段階(`ribbon`)、**実際に進化させた回数**(`evolution_count`。進化1回ごとに最大所持数+5。
  野生で進化後の姿を捕まえた場合は 0。省略すると進化段階ぶん進化させたとみなす)

食材はアイコンだけで名前が出ないことが多い。`PS lookup <名前>` で各枠の選択肢と個数を確認し、
アイコンと**個数**で照合して決める(個数が選択肢ごとに違うので区別できることが多い)。
それでも判別できなければユーザーに聞く。

### 2. 入力JSONを作って評価する

スクラッチパッドなどに JSON を書き、`PS eval` を実行する。

```json
{
  "name": "ピカチュウ",
  "level": 25,
  "nature": "いじっぱり",
  "subskills": ["きのみの数S", "おてつだいスピードM", "スキル確率アップS", "最大所持数アップM", "おてつだいボーナス"],
  "ingredients": ["とくせんリンゴ", "あったかジンジャー", "とくせんエッグ"],
  "skill_level": 2,
  "rp": 812,
  "ribbon": 0,
  "evolution_count": 1,
  "nickname": "",
  "memo": ""
}
```

- 食材は名前のほか `"A"/"B"/"C"`(lookup の表記)でも指定できる。
- 名前の表記揺れはある程度吸収する。見つからない場合は候補が出るので直して再実行。
- **RPチェックが「不一致」なら**、読み取りを見直す(レベル・せいかく・サブスキルの順番・食材・スキルLv)。
  どうしても合わなければ、その旨を添えて結果を出す。

### 3. 結果をユーザーに見せる

`eval` の出力(1日あたりの期待値の表・比較表)をもとに、次をまとめて日本語で返す。

1. 読み取った内容(ユーザーが誤読に気づけるように)と RP チェック結果
2. **個体ランク**: Lv80 時点で、同じポケモン(進化前なら最終進化)のあらゆる個体の中で**上位何%か**。
   とくいの指標(【とくい】印)を主役にする。例: スキルタイプならスキル回数/日の順位
3. **とくい**に対応する指標を主役にした評価
   - きのみタイプ → きのみエナジー/日
   - 食材タイプ → 食材個数/日(と食材ごとの個数/日。欲しい食材が何個取れるか)
   - スキルタイプ → スキル回数/日
   - オールタイプ(幻) → 3つすべて
4. 記録済み個体との比較結果: 「今回が強い / 前の方が強い / ほぼ同等」を **Lv80** の値で判定したもの
   (進化前は最終進化に換算して比較される)
5. せいかく・サブスキルの寸評(下の目安を参考に。断定しすぎず、用途によって変わる点は添える)
6. eval に「必須サブスキル: 未確認」と出たら、**必須サブスキルがあるか**も尋ねる(下の「必須サブスキル」参照)
7. 最後に **記録するかどうか・ステータス(厳選完了 / キープ)** を尋ねる

### 4. 記録する(ユーザーが了承した時だけ)

**ユーザーの了承なしに `save` / `update` / `delete` を実行しない。**

了承されたら `PS save <JSON> --status 厳選完了` (または `キープ`) を実行する。
以前の個体を置き換える場合(例: 「新しい方を厳選完了にして、前のはキープに」「前のは消して」)は、
ユーザーの指示どおりに `update --status` や `delete` も行う。

このリポジトリはクラウド環境で使われることがあり、コミットしないと記録が消える。
記録を変更したら `records/pokemon.json` をコミットして、作業中のブランチにプッシュする。

```bash
git add records/pokemon.json
git commit -m "記録: #<ID> <ポケモン名> Lv<レベル> (<ステータス>)"
git push -u origin <現在のブランチ>
```

## 必須サブスキル

ポケモンごとに「これがない個体は論外」というサブスキルを設定できる(ユーザーに頼まれた時だけ設定する)。

```bash
PS require ジュカイン きのみの数S                          # きのみの数S が必須
PS require ジュカイン "スキル確率アップS|スキル確率アップM"  # どちらか1つあればよい
PS require ジュカイン きのみの数S おてつだいボーナス        # 両方必須
PS require ジュカイン --clear                              # 解除
PS require サーナイト --none                               # 必須なしを確認済みとして記録
```

- **初めて評価するポケモン**(最終進化が `required_subskills.json` に無い。eval に「未確認」と出る)では、
  結果を見せる時に**必須サブスキルがあるかユーザーに確認する**。候補を寸評の目安から1〜2個提案するとよい。
  「必須なし」と言われたら `--none` で記録し、次回から聞かない。

- **きのみタイプ(とくい: きのみ)は、設定がなくても常に きのみの数S が必須**(`SPECIALTY_REQUIRED`)。
  個別の設定はこれに追加される。
- 設定は**最終進化の名前**で行う(キモリ・ジュプトルも、ジュカインの設定で評価される)。
- 上位%: 必須を満たす個体は、満たさない個体より**常に上**として計算する
  (満たさない個体は、満たす個体すべてより下)。eval の出力に満たしているかが表示される。
- 記録との比較: **同じ種族同士**で片方だけ必須を満たす場合、値に関係なく満たす方を強いと判定する。
- 設定を変えたら `records/required_subskills.json` もコミットする。

## 計算の前提

- **評価はLv80**(サブスキル5つ・食材3枠がすべて解放)。表は現在Lv・Lv60・Lv80、比較・判定・上位%は Lv80 の値。
- **銀タネ前提**: 自分の個体(今回・記録済み)は、サブスキルの S→M・M→L(スピード・食材確率・スキル確率・
  スキルレベル・最大所持数)をすべて銀タネで上げた想定で計算する(使用数の制限なし)。
  同じサブスキルは2つ持てないので、上げた先をすでに持っている場合はそのまま(例: M があれば S は S のまま)。
  上位%の比較相手(ランダムな個体)はタネなし。RPチェックは画面どおりのサブスキルで行う。
  `pokesleep.py` の `ASSUME_SILVER_SEED` で切り替え可能。
- おてつだい時間 = 基礎時間 × (501−Lv)/500 × せいかく(▲0.9 / ▼1.075) × (1 − 0.07×スピードS/M段階 − 0.05×おてつだいボーナス、最大35%減) × おやすみリボン補正
- 食材確率 = 基礎 × せいかく(▲1.2/▼0.8) × (1 + 0.18×食材確率アップS/M段階)。スキル確率も同様
- きのみ個数/回 = 1(きのみタイプ・オールは2) + きのみの数S
- 食材は解放済みの枠から等確率
- **1日 = 起きている16時間 + 寝ている8時間**
  - 起きている間はこまめにタップする想定で、所持数は溢れない
  - 寝ている間はタップできない。最大所持数(基礎 + 進化1回ごとに+5 + 最大所持数アップS/M/L で+6/12/18 + リボン)が
    満杯になると、以降は食材が取れず(きのみの「つまみぐい」だけ)、**スキル判定も止まる**
  - 夜のスキルは寝ている間 1回までストック(スキル・オールタイプは2回まで)
  - 満杯になるタイミングは確率的なので、所持数の推移を確率分布で追って期待値を出している
- **上位%** は、せいかく(25種均等)・サブスキル5つ(重複なし、全17種が同じ確率)・食材の並び(均等)の
  全組み合わせを計算し、今回の個体以上の値になる確率。幻(ダークライ等)は食材を選べるので今回の食材で固定。
  **食材の順位は、その個体が一番多く取れる食材の個数/日**で比べる(ほかの個体もその食材の個数で比べる)。
  サブスキルの出現率の差は考慮しない(`pokesleep.py` の `SUBSKILL_WEIGHT` で変更可能)
- **含めていないもの**: げんきによる速度変化、チームの他メンバーのおてつだいボーナス、スキルの効果量、イベント・フィールドボーナス。
  **個体同士の相対比較用の値**であり、実際の獲得量とはずれる。
- 記録済み個体との比較は、とくいが同じ個体を主に、**とくいが違う個体は [参考] として**後ろに並べる。
- 食材の比較は**共通の食材ごとに、その食材の個数/日**で比べる。
- 判定は Lv80 の値で ±1% 以内を「ほぼ同等」。
- 基礎データの出典: [pokesleep-tool](https://github.com/nitoyon/pokesleep-tool) (MIT)。
  新ポケモンや数値調整に追従するには `python3 .claude/skills/pokesleep-iv/scripts/update_data.py` を実行してコミットする。

## 寸評の目安

| とくい | 当たりのせいかく | 当たりのサブスキル |
|---|---|---|
| きのみ | おてつだいスピード▲ | きのみの数S、おてつだいスピードM/S、おてつだいボーナス |
| 食材 | 食材おてつだい確率▲、おてつだいスピード▲ | 食材確率アップM/S、おてつだいスピードM/S、おてつだいボーナス、最大所持数アップL/M |
| スキル | メインスキル発生率▲、おてつだいスピード▲ | スキル確率アップM/S、スキルレベルアップM/S、おてつだいスピードM/S、おてつだいボーナス |

- どのタイプでも おてつだいボーナス・げんき回復ボーナス はチーム全体に効くので評価が高い。
  ゆめのかけらボーナス・リサーチEXPボーナス は育成・資源目的では当たり。
- 早いレベル(Lv10・25)で良いサブスキルが開くほど、育成途中から活躍できる。
- 所持数が夜のうちに満杯になりやすい個体(「朝までに所持数が満杯になる確率」が高い)は、最大所持数アップの価値が上がる。
- 食材タイプは「欲しい食材が何枠目に来ているか」で価値が大きく変わるので、食材の並び(例: AAB)にも触れる。
